# Artemisis — кейс 2 «Номер, который знает гостя»

Python-бэкенд получает данные заезда, строит сценарий номера по правилам сна и обрабатывает просьбы гостя через LLM и симулятор устройств. Контракт проверки — `POST /run`: авторизация токеном из входящего запроса, получение набора и возврат JSON с сеансами и ответами.

## Запуск

Для ветки `dev` нужны Docker с Compose, Google AI Studio API key и выданный команде `api.token`. Ключи храните в локальном `.env` или переменных окружения, не в Git. Для стенда организаторов используйте ветку `main`: она не содержит Google-провайдера.

Linux, macOS или WSL из корня репозитория:

```bash
cp .env.example .env
export HACK_TEAM_TOKEN="$(tr -d '\r\n' < '/путь/к/api.token')"
export GEMINI_API_KEY='<ключ Google AI Studio>'
docker compose up -d --build
```

Документация API доступна на `http://localhost:8000/docs`. Для ручной проверки через Python 3.11 установите `pip install -r requirements.txt`, задайте `HACK_API_URL`, `HACK_TEAM_TOKEN`, `LLM_PROVIDER=google`, `GEMINI_API_KEY` и выполните `uvicorn app.main:app --host 127.0.0.1 --port 8000`.

Демонстрационные сеансы создаются отдельно от зачётного `/run`; командный токен остаётся на сервере. При подготовке используется профиль и заметки, без вызова LLM. Прогон симулятора действует 45 минут; после истечения API возвращает 410, и для продолжения нужен новый сеанс. История нового API хранится в SQLite и сохраняется при перезапуске контейнера. Для обработки просьб в чате требуется доступная LLM.

### API для фронтенда

Заполните `FRONTEND_ADMIN_KEY` в `.env` случайным значением длиной не менее 16 символов (например, `openssl rand -hex 32`); задайте также `HACK_TEAM_TOKEN` и `GEMINI_API_KEY`. `FRONTEND_ORIGINS` — разрешённые адреса фронтенда через запятую, по умолчанию локальный Vite на порту 5173. Перезапустите контейнер после изменения настроек.

- `POST /api/v1/sessions` с заголовком `X-Admin-Key` и телом `{}` создаёт отдельный dev-сеанс. Необязательный `record_id` выбирает заезд из dev-набора. Ответ содержит `access_token` гостя и `room` с состоянием и расписанием. Ключ создания хранится на доверенной серверной стороне: не встраивайте его в публичный frontend.
- Все следующие запросы принимают `Authorization: Bearer <access_token>`: `GET /api/v1/room` — состояние и расписание, `GET /api/v1/room?at=<ISO8601>` — просмотр состояния на указанное время без изменения текущего времени; `POST /api/v1/time` с `{"at":"...+03:00"}` меняет виртуальное время сеанса.
- `GET /api/v1/catalog` возвращает каталог устройств симулятора и доступные треки текущего набора.
- `POST /api/v1/actions` с `{"device_id":"light","values":{"brightness":30}}` меняет устройство без LLM; допустимые поля и диапазоны проверяются сервером. `GET /api/v1/messages` возвращает историю, `POST /api/v1/messages` с `{"text":"Сделай прохладнее"}` — ответ, статус выполнения и состояние номера.
- Ошибки: 401 — нет доступа, 404 — сеанс не найден, 410 — истёк, 422 — неверные данные, 502 — ошибка LLM или симулятора, 503 — неполная конфигурация. Формат FastAPI: `{"detail":"..."}`.

SQLite и токены сеансов — основа для интеграционного MVP, не полноценные учётные записи и не авторизация отеля. Сейчас используется один процесс приложения и dev-набор организаторов. Старый общий экран по умолчанию отключён; включайте `ENABLE_LEGACY_DEMO=true` только для локальной демонстрации, поскольку его методы не имеют авторизации и все пользователи разделяют один номер.

Локальные тесты: `python -m unittest discover -s tests -v`. Для сверки с dev-эталоном запустите `docker compose exec -e HACK_TEAM_TOKEN app python -m tools.dev_run --evaluate`. Внимание: dev-прогон с `--evaluate` вызывает LLM и расходует общую квоту команды.

Структура: `app/` — сервер, работа с LLM и симулятором, `app/static/` — интерфейс, `tools/` — dev-проверка, `tests/` — тесты, `start.sh` — запуск на стенде.

## ИИ

Модель извлекает настройки и краткую память из профиля и истории, интерпретирует просьбу и формирует план действий. Код проверяет схему и допустимые значения устройств перед отправкой в симулятор; некорректный план повторяется до трёх раз, затем возвращается отказ. При отказе модели или ошибке API прогон может завершиться ошибкой.

В `dev` по умолчанию используется Google: задайте `GEMINI_API_KEY` в `.env` или окружении. `GEMINI_BASE_URL` по умолчанию указывает на прокси команды, который получает ключ и содержимое запросов и пересылает их в Google. Для прокси организаторов задайте `LLM_PROVIDER=sain` и переменные `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`. Ветка `dev` не предназначена для сдачи без проверки ограничений хакатона. Исходящие запросы ограничены в процессе приложения; ответы 429/5xx повторяются с задержками 5, 10 и 20 секунд. Квота общая для команды и зачётного прогона. В логе успешного прогона указываются агрегированные числа запросов и токенов; данные гостей и ключи не выводятся.

Расход: прежняя версия на полном dev-наборе через прокси организаторов использовала 225 026 токенов на 49 вызовов, после чего история была сокращена. Полный расход итоговой версии с этой моделью не измерен: повторная попытка прервалась из-за исчерпания общей квоты. На локальной проверке через Google предыдущая версия использовала 87 154 токена на 43 вызова. Это измерение другого провайдера, оно не является прогнозом расхода на стенде.

## Журнал решений

- Естественный язык и извлечение предпочтений переданы LLM; диапазоны и поля команд проверяет код.
- Отказались от передачи всей истории при каждой просьбе: прежний полный dev-прогон израсходовал 225 026 токенов. Оставлены отбор по словам и краткая память, но такой отбор может пропустить важную запись.
- Отказались от отдельного ответа на каждую реплику внутри одной просьбы после сверки с dev-эталоном: теперь просьба получает один ответ.
- Отказались от повторного использования сеанса зачётного `/run` для демонстрации: после сохранения ответа организаторы закрывают его для изменений. Демонстрация создаёт отдельный dev-сеанс.
- Проверка `validate` подтверждает формат, но не качество. На локальном dev-прогоне через Google предыдущая версия совпала с эталоном по 29 из 38 просьб, а приблизительная проверка расписания прошла для пяти заездов. Это не результат модели организаторов и не официальная итоговая оценка.
- Перевод времени отбоя учитывает домашний часовой пояс, пояс отеля и сдвиг при разнице от трёх часов. Для каждой просьбы и заезда используется отдельный сеанс симулятора.
