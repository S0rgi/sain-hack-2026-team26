# Artemisis — номер, который знает гостя



[![Presentation](https://img.shields.io/badge/Презентация-PDF-2ea44f?style=for-the-badge&logo=adobeacrobatreader&logoColor=white)](final-pitch.pdf)
[![Live Demo](https://img.shields.io/badge/Стенд-team26.hack.be--healthy.tech-blue?style=for-the-badge)](https://team26.hack.be-healthy.tech)


Веб-демо ведёт гостя от заселения до выезда. Оно строит план сна по профилю, заметкам и времени отеля, показывает состояние устройств в течение ночи и выполняет просьбы в той же сессии симулятора. На выезде гость получает настройки для дома и может перенести подходящие из них в следующий заезд.

## Локальный запуск

```bash
cp .env.example .env
```

Заполните `HACK_TEAM_TOKEN` из выданного команде `api.token`. Для общего номера на локальном компьютере задайте `ENABLE_LEGACY_DEMO=true`. По умолчанию репетиция использует `HACK_RUN_STAGE=dev`. Явные команды и план сна работают без LLM. Для неоднозначных просьб настройте серверный провайдер.

```bash
docker compose up -d --build
```

Откройте [номер](http://localhost:8000) и нажмите «Заселиться». Выберите «Ночь» и отправьте просьбу «Поставь температуру 21 градус и яркость 150 процентов». На выезде можно проверить изменения и перенести подходящие настройки в повторный заезд. [Документация локального API](http://localhost:8000/docs)

## Защита

Установите `HACK_RUN_STAGE=final`, `LLM_PROVIDER=sain` и серверные `HACK_TEAM_TOKEN`, `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`. Если на стенде выданы переменные `LLM_*` и нет явного `LLM_PROVIDER`, приложение выбирает `sain`. Общий номер включайте только для компьютера защиты или закрытого сервера.

Приложение само вызывает `POST /runs` с `{"case": 2, "stage": "final"}`, читает набор по токену прогона и использует один сеанс для расписания и живых действий. Локальное время ограничено окном заезда. Финальный набор и время жизни прогона определяет API организаторов. Зачётный `POST /run` сохранён для пакетной проверки dev. [Контракт организаторов](https://hack-api.be-healthy.tech/docs/json)

Для голоса задайте `HACK_VOICE_ENABLED=1` и отдельный случайный `HACK_VOICE_ACCESS_KEY` из 16–256 печатных ASCII-символов без пробелов. Его можно сгенерировать командой `openssl rand -hex 16`. Введите этот ключ в интерфейсе при первом использовании голоса. Он действует в открытой вкладке. Запросы к прокси организаторов используют серверный `LLM_API_KEY`. Имена моделей задают `HACK_STT_MODEL` и `HACK_TTS_MODEL`. Значения по умолчанию `gpt-transcribe` и `tts-1` требуют доступа в прокси. Распознанную фразу можно исправить перед отправкой.

Ветка `main` использует только прокси организаторов. Секреты хранятся в серверном окружении или игнорируемом Git файле `.env`.

## Отдельные гостевые сеансы

`/api/v1` предназначен для dev-интеграций с отдельными гостевыми токенами. Создание сеанса требует `FRONTEND_ADMIN_KEY` на доверенном сервере. `FRONTEND_ORIGINS` задаёт разрешённые адреса клиентов через запятую. SQLite на томе Compose хранит время и историю отдельных сеансов.

| Маршрут | Назначение |
| --- | --- |
| `POST /api/v1/sessions` | Создать dev-сеанс, при необходимости передать `record_id` |
| `GET /api/v1/room` | Прочитать состояние, с `?at=` просмотреть другое время |
| `POST /api/v1/time` | Изменить текущее время сеанса |
| `GET /api/v1/catalog` | Прочитать устройства и треки |
| `POST /api/v1/actions` | Применить проверенное прямое действие |
| `GET /api/v1/messages`, `POST /api/v1/messages` | Прочитать историю или отправить просьбу |

`POST /api/v1/sessions` принимает `X-Admin-Key`. Остальные маршруты принимают выданный гостевой `Authorization: Bearer <access_token>`. Истёкшая сессия возвращает 410 до очистки и 404 после удаления. Интервал очистки задаёт `SESSION_CLEANUP_INTERVAL_SECONDS`, по умолчанию 60 секунд. Встроенный интерфейс защиты использует общий номер, отдельный от `/api/v1`.

## Проверки

```bash
python -m unittest discover -s tests -v
docker compose exec app python -m tools.dev_run --evaluate
```

Для проверки сохранения гостевого сеанса при пересоздании контейнера можно запустить `pwsh -File tests/test_api_v1_docker.ps1` с локально собранным образом. Этот тест использует подменённый симулятор.

Команда `tools.dev_run --evaluate` создаёт реальный dev-прогон и может расходовать командную квоту модели. Проверка формата и сравнение с открытым эталоном не заменяют оценку жюри.

## Журнал решений
1. **Отказ от LLM для правил R1–R8**: вызов LLM на анализ профиля тратил 225k токенов и занимал 12 секунд. Заменили на детерминированный движок (0 токенов, <5 мс).
2. **Fast Path для команд устройств**: простые фразы («теплее», «приглуши свет») исполняются регулярными выражениями без обращения к сети.
3. **Отказоустойчивость при HTTP 429**: при превышении лимита шлюза организаторов запрос подхватывает локальный fallback, исключая пятисотые ошибки.
4. **Изоляция аудиопотока**: аудиоданные транскрибируются в потоке памяти без сохранения на диск (защита от утечки дескрипторов).
